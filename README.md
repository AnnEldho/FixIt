# FixIt — See it. Report it. Fix it.

A community issue-reporting app built with **Flutter** and **Firebase**.
Citizens report problems (potholes, street lights, waste, water, drainage…) and
track them from *Reported → In Progress → Resolved*. Admins review every report
and update its status.

## Features

- Email/password registration, login, forgot-password, persistent session
- Report an issue with category, description and location
- Live dashboard with stats and recent reports (real-time Firestore streams)
- My Reports list and detailed status timeline
- Profile tab with logout
- **Built-in admin account** (default email + password, no registration)
- **Admin area**: overview stats, category breakdown, all reports, filter and change status
- Firestore security rules (users can only see their own reports)

## Tech / Database

| Part | Technology |
|------|------------|
| UI | Flutter (Material 3, dark theme) |
| Auth | Firebase Authentication (email + password) |
| Database | Cloud Firestore (NoSQL) |

### Data model

```
users/{uid}
  name, email, phone, role ('user' | 'admin'), createdAt

issues/{issueId}
  title, description, category, location,
  status ('Reported' | 'In Progress' | 'Resolved'),
  reportedBy (uid), reportedByEmail, createdAt, updatedAt
```

## Folder structure

```
lib/
├── main.dart                 # Firebase init + runApp
├── app.dart                  # MaterialApp, theme, AuthGate
├── firebase_options.dart     # generated by FlutterFire CLI
│
├── core/                     # app-wide, feature-independent code
│   ├── constants/            # collection names, roles, statuses, categories
│   ├── errors/               # AppException (friendly error messages)
│   ├── theme/                # AppTheme (colors + ThemeData)
│   └── utils/                # validators, date formatter, snackbar helper
│
├── data/                     # everything that talks to Firebase
│   ├── models/               # UserModel, IssueModel
│   └── repositories/         # AuthRepository, UserRepository, IssueRepository
│
├── features/                 # one folder per feature (screens + widgets)
│   ├── auth/                 # AuthGate, login, register
│   ├── home/                 # HomeShell (bottom navigation)
│   ├── dashboard/            # Home tab
│   ├── issues/               # report, my reports, details, cards, timeline
│   ├── profile/              # Profile tab
│   └── admin/                # Admin panel
│
└── shared/widgets/           # reusable UI: text field, button, stat card, …
```

Rule of thumb: **screens never call Firebase directly** — they go through a
repository, which converts Firebase errors into friendly `AppException`s.

## One-time Firebase setup

1. Firebase Console → **Authentication → Sign-in method** → enable **Email/Password**.
2. **Firestore Database** → *Create database* (production mode).
3. Firestore → **Rules** → paste the contents of [`firestore.rules`](firestore.rules) → **Publish**.
4. **Admin login (no registration):** on the login screen use
   `admin@fixit.com` / `Admin@123`. The first time, the app creates this admin
   account automatically. Admins get their own home (Overview, all Reports,
   Profile). Change the credentials in `lib/core/constants/app_constants.dart`
   (`DefaultAdmin`) and keep `adminEmail()` in `firestore.rules` in sync.

## Install on your phone WITHOUT a USB cable

A **release** APK is a normal standalone app — once installed it runs by itself
(it only needs internet for Firebase).

### Option A — build the APK, send it to the phone (easiest)

```bash
flutter build apk --release
```

The file is `build/app/outputs/flutter-apk/app-release.apk`.
Send it to your phone (Google Drive, WhatsApp/Telegram "document", email, or
Nearby Share), open it on the phone and tap **Install**
(allow *Install unknown apps* for that app when asked).

### Option B — Wireless debugging (Android 11+, same Wi-Fi as the laptop)

1. Phone: *Settings → Developer options → Wireless debugging* → ON
   (enable Developer options by tapping *Build number* 7 times).
2. Tap **Pair device with pairing code**. On the laptop:
   ```bash
   adb pair <ip>:<pairing-port>      # enter the 6-digit code
   adb connect <ip>:<connect-port>   # port shown on the Wireless debugging screen
   ```
3. Install the standalone release build:
   ```bash
   flutter run --release
   ```
   After this you can unplug everything; the app stays installed.

### Option C — let GitHub build it (no Flutter needed on the laptop)

Push to `main`. GitHub Actions (`.github/workflows/build_apk.yml`) builds the
APK; open the run → **Artifacts → fixit-release-apk**, download on the phone
and install.

## Notes

- Release builds are signed with the debug key — fine for demos/microproject.
  For Play Store publishing, create your own keystore and signing config.
- `INTERNET` permission is declared in the main Android manifest (required for
  release builds to reach Firebase).
